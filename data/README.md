# Данные

В файле представлено описание данных: карточки товаров, пары-кандидаты с метками и набор для оценки. Это то, что предоставляется оргами. 

Карточка - это название, категория и JSON атрибутов. Пары уже отобраны ретривером, задача сводится к классификации.

Всё, что ниже, — надстройка, которую мы построили поверх этого.

## Разметка организаторов

Кроме человеческой разметки нам выдавался `matches_llm.parquet` — 11 187 780 пар с вероятностной меткой. Значения кратны 1/9, то есть за каждой парой стоит девять голосов. По описанию организаторов это дистиллят модели, видевшей в том числе изображения товаров. Состав девяти голосов не публиковался и нам неизвестен.

Распределение меток сильно смещено: 7 184 663 пары имеют 0, ещё 1 223 955 имеют 1, а весь промежуток между ними - около 2.8 млн пар. Пограничные значения 4/9 и 5/9 встречаются у 521 704 пар.

Обучающий пул `llm_pairs_2p5m.parquet` - это подвыборка 2 500 000 строк из этого файла, `np.random.default_rng(42).choice` без возвращения, отсортированная по индексу. `items_llm_2p5m.parquet` — 3 789 036 карточек, ровно множество концов этих пар, отобранных из `items.parquet` с сохранением исходного порядка.
Скрипт: `pipeline/build_source_sample.py`.

## Собственная разметка

`pipeline/label_with_teacher.py` - это наш учитель, `Qwen/Qwen3-30B-A3B`. Он не генерирует текст: сравниваются логиты вербализаторов `да` и `нет` на первой позиции ответа, оба обязаны быть ровно одним токеном. Скрипт останавливается, если это условие нарушено: `tok.encode("Да")[0]` возвращает префиксный токен `Д`, и без проверки разметка получается некорректной без видимой ошибки.

Варианты промпта: `short`, `medium`, `fewshot`, плюс флаг `--symmetric` для обратного порядка карточек.

Эта линия появилась на две недели позже старта и в финальные решения не вошла: чекпоинты трёх выпущенных решений обучены без неё.

## Транзитивное замыкание

`pipeline/build_transitive_pairs.py`. Из уверенных пар строится граф: ребро считается положительным при метке не ниже 8/9 и отрицательным при не выше 1/9. Внутри компоненты связности все пары объявляются положительными, между компонентами при наличии явного отрицательного ребра — отрицательными. Размер компоненты ограничен восемью товарами, объём добавки — полутора миллионами пар каждого знака.

Ограничение на размер компоненты существенное. Аудит замыкания показал, что среди выдуманных пар, для которых метка известна, от 34% до 57% размечены как разные, а held-out эксперимент восстанавливает замыканием лишь 8.24% убранных положительных рёбер. Отношение "тот же товар" в этой разметке не является отношением эквивалентности, и чем крупнее компонента, тем сильнее дрейф.

Скрипт по умолчанию строит вариант без запрета по content-alias двойникам — именно на нём обучен выпущенный чекпоинт (2 277 728 пар). Флаг `--content_alias` включает расширенный запрет и даёт очищенный вариант на 2 247 298 пар, который в обучение выпущенных решений не входил.

Отдельно проверялись транзитивные отрицательные пары: правило «A равно B и A не равно C, значит B не равно C» право в 77.49% случаев при доле отрицательных 76.59%. Информации сверх базовой ставки нет, поэтому в обучении используются только транзитивные положительные.

## Стратифицированный пул

`pipeline/build_stratified_pool.py`. Равномерная выборка из размеченного пула расходуется неудачно: 64% приходится на отрицательные пары, а категории одежды и обуви, которые сильнее всего тянут macro-AP вниз, получают около тысячи положительных примеров на шестьсот тысяч строк.

Страты - категория, полоса метки и полоса лексического сходства названий. Квоты выравнивают двадцать категорий, поднимают долю положительных, добавляют лексически близкие отрицательные пары (самый вредный для AP класс) и прореживают тривиальные.

На лидерборде стратификация дала минус 0.0079 и в финальные решения не вошла.

## Валидация

Основная — fold-0 человеческой разметки: 73020 пар, разбиение по компонентам связности, из обучения исключены полностью. Отбор вариантов на половине A (чётный хеш идентификатора первого товара), подтверждение на половине B.

`pipeline/build_holdout.py` строит дополнительный набор `hardval`: пары из размеченного пула, не попавшие в обучающую выборку, только уверенные метки, положительные проредены до 10% на категорию, чтобы приблизить долю
положительных к тестовой. Он использовался как диагностика удержания качества, а не как селектор моделей: он не изолирован по товарам относительно пула предобучения и размечен тем же учителем.

Интересное примечание: тест размечен не людьми, поскольку любое изменение, смещающее обучение к человеческой конвенции, не растёт на тесте. Четыре независимых подтверждения.

## Порядок запуска

    python pipeline/label_with_teacher.py --model Qwen/Qwen3-30B-A3B --variant medium
    python pipeline/label_with_teacher.py --model Qwen/Qwen3-30B-A3B --variant medium --symmetric
    python pipeline/build_source_sample.py
    python pipeline/build_folds.py
    python pipeline/build_human_val.py
    python pipeline/build_transitive_pairs.py
    python pipeline/build_exclusions.py
    python pipeline/build_holdout.py

Что получается на выходе:

| скрипт | результат |
|---|---|
| `label_with_teacher.py` | голоса учителя, по файлу на вариант промпта |
| `build_source_sample.py` | обучающий пул и карточки к нему |
| `build_folds.py` | разбиение человеческой разметки на фолды |
| `build_human_val.py` | валидация, fold-0 |
| `build_transitive_pairs.py` | транзитивно замкнутые пары |
| `build_exclusions.py` | список исключений, чтобы валидация не протекала |
| `build_holdout.py` | диагностический набор с тестовой долей положительных |
| `build_stratified_pool.py` | стратифицированный пул, в финальные решения не вошёл |

Пути берутся из переменных окружения `ECUP_DATA` и `ECUP_OUT`, по умолчанию `data` и `runs`.
